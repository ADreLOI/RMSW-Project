\subsection{Work Procedure and Data Collection}

The work will proceed from the simplest verifiable case to the final comparison. First, a one-USV survey and a two-USV fixed partition will be checked under reliable and disconnected links; the fixed partition should be communication-independent. Next, the common online allocator and reactive resynchronization behavior will be implemented, and a hand-checked trace will confirm how stale shared state changes an allocation decision. The outage predictor will then be evaluated separately for false alarms, missed detections, and useful lead time before its pre-outage exchange and task-reservation action is added.

A pilot will be used to check runtime, variability, failure cases, and whether every planned metric can be reconstructed from the logs. The final configurations and analysis rules will then be frozen. Strategies will be run on paired initial conditions and communication disturbances, with separate random streams so that policy-specific decisions do not change the common scenario. Seeds, configurations, raw logs, and timed-out runs will be retained. If the predictive intervention cannot be evaluated fairly within the course period, the higher-fidelity extension will be removed and the study will report the narrower reactive-versus-predictive comparison in the validated 2D model.
